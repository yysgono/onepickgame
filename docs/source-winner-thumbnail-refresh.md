# 제작 페이지 원본 월드컵 썸네일 재확인 수정

## 확인한 문제
관련 링크를 처음 조회한 시점의 기본 사진 또는 서버가 보낸 초기 이미지를 계속 사용하는 경로가 있었습니다. 티어표 제작 화면에서 같은 ID의 전체 후보가 뒤늦게 도착해도, 기존 효과가 ID·언어·분류만 의존해 원본 카드의 사진을 다시 계산하지 않았습니다. 서버 통계 조회가 일시적으로 실패해 기본 두 장이 들어간 경우도 브라우저에서 재확인하지 않았습니다.

## 수정
- 전체 후보가 준비된 후 원본 월드컵 카드의 순위 이미지만 독립적으로 확인합니다. 후보 배열이 실제로 갱신되면 다시 계산합니다.
- `_homeCardOnly` 부분 데이터 상태에서는 순위를 확정하지 않습니다.
- 서버의 초기 이미지가 있어도 브라우저에서 현재 홈과 같은 공개 통계·현재 사용자 세션으로 재확인합니다.
- 사진 URL이 바뀔 때 이미지 컴포넌트를 새로 연결해 지연 로딩이 이전 URL 상태에 멈추지 않게 합니다.
- 홈과 동일한 누적 우승 횟수 → 대결 승리 횟수 정렬 함수를 유지합니다. 이미지 주소와 파일은 재사용합니다.
- 관련 작품·템플릿 목록은 다시 불러오지 않습니다. 같은 후보 배열로 동시에 발생한 순위 조회는 진행 중인 하나의 요청으로 합칩니다. 완료 후 요청 캐시는 제거하므로 오래된 순위가 영구 고정되지 않습니다.
- 원본이나 언어가 바뀌면 이전 요청의 결과가 새 카드에 적용되지 않도록 처리합니다.
- 통계가 실제로 없으면 홈과 같이 기본 후보 두 장을 사용합니다. 통계 조회 실패는 정상적인 빈 통계와 구분합니다.

이 수정은 구절판과 티어표 제작 페이지의 원본 월드컵 카드 모두에 적용됩니다. 기존 카드 제목 번역·5개씩 넘기기·작성 중인 배치는 유지합니다.

## 적용 및 검증
앞선 카드 업데이트가 적용된 프로젝트에 같은 경로로 덮어쓰고 서버와 프런트엔드를 함께 빌드·배포하세요. SQL·환경변수 추가는 없습니다. 운영 배포·운영 DB 변경은 하지 않았습니다.

검증: CRA 빌드, 부분 후보 1·2 사진 상태에서 전체 후보 도착 후 실제 우승 4·3으로 교체되는 회귀 사례, 같은 ID의 후보 사진 갱신, 일반 재렌더 시 조회 없음, 동시 조회 합치기, 기존 우승 정렬·카드 넘김 검사. 한국어/영어 구절판·티어표의 실제 빌드 JS 실행도 확인했습니다. 사용자가 보고 있는 특정 운영/로컬 페이지의 네트워크 기록을 직접 읽은 것은 아닙니다.
