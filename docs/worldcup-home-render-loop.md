# 월드컵 홈 축소 후 복원 시 갱신 반복 수정

## 확인한 원인

useWorldcupHomePages가 렌더마다 cups 배열을 새로 만들었습니다. Home의 썸네일 로딩 effect가 이 배열을 의존해 다시 실행되고, 캐시에서 받은 동일한 이미지도 새 상태 객체로 저장했습니다. 상태 저장 → 렌더 → 새 cups 배열 → 캐시 로딩 → 새 상태 저장이 반복됐습니다. 네트워크 재요청이 없어도 React 작업은 반복됩니다.

이전 빌드에 React commit 계측을 넣어 조작 없는 600ms 동안 354회 갱신을 재현했습니다. 이 때문에 창 크기 변경 이후에도 브라우저가 반복 작업을 계속할 수 있습니다. 앞선 CSS 너비 수정만으로는 이 반복을 해결할 수 없었습니다.

## 변경

1. 실제 페이지 rows가 바뀔 때에만 cups 배열을 다시 만듭니다(useMemo).
2. 캐시 이미지가 현재 저장된 URL 배열과 같으면 이전 상태 객체를 그대로 반환합니다.
3. 화면 너비 변경은 썸네일 effect의 명시적인 의존성으로 포함합니다. 화면이 넓어져 새로 보이는 후보도 정상 처리하며, 같은 이미지로는 추가 갱신하지 않습니다.
4. 이전 ZIP의 반응형 배치와 resize 이벤트 프레임 단위 처리도 포함합니다.

## 검증

프로덕션 빌드 성공 및 git diff --check 통과.

실제 빌드 번들을 JSDOM에서 실행해 한국어·영어 각각 확인했습니다. 초기 로딩 후 600ms 동안 추가 commit 0회, 1900→1100→500→1900px 연속 resize 이후 600ms 동안 추가 commit 0회였습니다. 기존 카드 DOM 유지, 저장된 썸네일 재사용(한 번 조회), 최초 홈/activity 조회 재시작 없음 및 JavaScript 오류 없음을 확인했습니다.

이 검증은 실제 빌드의 JavaScript와 상태 갱신에 대한 검사입니다. 사용자의 Windows Chrome/Edge 창을 직접 조절한 시각적 검증은 수행하지 못했습니다.

## 적용

src/components/Home.js, src/hooks/useWorldcupHomePages.js, src/styles/homeResponsive.css를 같은 경로에 덮어쓰고 프런트엔드를 빌드·배포하세요. 이전 수정들이 적용된 프로젝트를 기준으로 합니다. 새 SQL 및 환경 변수는 필요 없습니다. 실서비스 배포는 수행하지 않았습니다.

이 ZIP은 앞선 onepickgame-worldcup-home-resize-fix.zip을 대체합니다. 적용 후 창을 아주 좁게 줄인 다음 최대화했을 때 페이지 폭·클릭·스크롤이 정상인지 확인하세요.
