# 퀴즈 홈과 카테고리의 페이지 단위 조회

적용 파일은 src/components/QuizPage.js, src/hooks/useQuizPages.js, src/utils/quizListPager.js, src/utils/supabaseQuizApi.js, quiz-seo.cjs입니다. 새 파일도 전부 복사한 뒤 최신 소스로 빌드·배포하세요. 추가 SQL과 패키지 설치는 없습니다.

- 처음에는 10개를 표시하고, 다음 페이지 확인용 1개를 더해 최대 11개만 조회합니다. 표시하지 않은 나머지 전체 목록을 미리 받지 않습니다.
- 더보기는 다음 10개를 추가 조회합니다. 기존 전체보기 버튼은 직접 눌렀을 때만 페이지를 이어서 조회합니다. 기존 최대 60개 한계를 없앴습니다.
- 모든 퀴즈 카테고리, 언어, 검색, 정렬, 내 목록 조건은 DB 조회에 적용합니다. 조건을 바꾸면 첫 페이지부터 다시 시작하며 이전 요청 결과가 뒤늦게 화면을 덮지 않습니다.
- 16개 언어 번역 제목·설명 검색 수정도 유지했습니다.
- 인기순/최신순의 값이 같을 때 ID로 정렬해 다음 페이지 경계를 안정화했습니다.
- 조회 실패 시 기존 카드는 유지하고 같은 범위를 재시도합니다.
- 최근 등록 목록은 현재 언어·카테고리의 최신 6개를 제목·날짜 위주로 별도 조회합니다. 인기 카드 중 날짜만 재정렬하던 동작을 정리했습니다.
- 최근 플레이 목록은 기존 로그 범위와 표시 기준을 유지하며, 연결된 퀴즈의 제목·날짜만 조회합니다.
- 모바일, 검색 중, 내 목록 등 최근 목록 박스가 숨겨진 화면에서는 해당 박스 조회를 하지 않습니다.
- 서버 초기 HTML도 10개만 제공하고 카테고리와 정렬 조건을 유지합니다. 개인 목록 초기 HTML은 공개 퀴즈 목록을 조회하지 않고 noindex/no-store로 처리합니다.

티어표 카테고리는 기존 코드에서 12개 표시 + 다음 페이지 확인용 1개 조회가 이미 적용돼 있습니다. 전체·게임·연예인·애니·음식·스포츠·기타 필터와 다음 페이지 범위를 검사했고, 이번에 티어표 코드는 변경하지 않았습니다.

검증: 실제 React QuizPage에서 초기 10개, 더보기, 중복 클릭, 60개를 넘는 전체보기, 검색, 모든 카테고리·정렬·언어·내 목록 전환, 숨긴 박스 조회 제외, 오류 재시도. API 필터·정렬·범위 검증, 서버 초기 HTML 검증, 운영 DB 읽기 전용 요청으로 페이지 경계와 티어표 카테고리 필터 확인. React production build 성공.
