# 종합 홈과 이상형 월드컵 목록 분리

홈에서 다섯 게임을 소개하고, 기존 월드컵 목록 화면을 `ideal-type-world-cup` 주소에서 제공합니다.

홈 API가 없거나 실패할 때의 카드 조회 보완은 [홈 데이터 오류 수정](platform-home-data-fix.md)에 정리했습니다. 이 묶음에는 해당 수정도 포함합니다.

## 주소

| 화면 | 한국어 | 영어 |
| --- | --- | --- |
| 종합 홈 | `/ko` | `/` (`/en`의 대표 주소도 `/`) |
| 이상형 월드컵 목록 | `/ko/ideal-type-world-cup` | `/en/ideal-type-world-cup` |
| 기존 월드컵 시작·통계 | `/ko/select-round/:id`, `/ko/result/:id` 유지 | 기존 주소 유지 |
| 티어표·퀴즈·구절판·랜덤 뽑기 | 기존 주소 유지 | 기존 주소 유지 |

20개 언어에 동일한 소문자 슬러그를 적용했습니다. 월드컵을 복제하거나 ID를 바꾸지 않습니다. 티어표·구절판 프리셋의 원본 월드컵 ID와 후보 데이터, 기존 저장 결과도 그대로 사용합니다.

## 홈 화면

최신 설명·중앙 헤더·좌우 여백과 카드 디자인 및 티어표 미리보기는 [홈 화면과 카드 수정](platform-home-layout-cards.md)에 정리했습니다.

섹션을 아래 순서로 한 줄씩 배치합니다. 각 섹션 제목과 ‘전체보기’는 같은 목록으로 연결됩니다.

1. 이상형 월드컵
2. 퀴즈 맞히기
3. 티어표
4. 최애 구절판 취향표
5. 랜덤 뽑기

각 섹션은 기존 크기의 카드를 가로로 넘깁니다. 본문에는 양옆 여백을 두고 스크롤바는 숨깁니다. 처음에는 12개씩 읽고, 다음 카드 이동 시 필요한 페이지를 이어 읽습니다. 게임 선택 박스 아래에서도 20개 언어를 선택할 수 있습니다. 월드컵·퀴즈·랜덤 뽑기는 기존 누적 플레이 수, 티어표·구절판은 조회수 내림차순입니다. 제목에 ‘인기’라는 말을 붙이지 않습니다. 랜덤 뽑기는 기존 모드별 통계로 정렬하며 프리셋별 통계를 새로 만들지 않습니다.

월드컵 카드는 기존 공용 썸네일 저장소에 있는 1·2위 후보 이미지를 재사용합니다. 저장된 썸네일이 없으면 첫 두 후보의 이미지 경로를 사용합니다. 기존 후보 소개문·후보 수를 표시하기 위해 해당 페이지의 공개 후보 메타데이터를 읽지만, 전체 후보 배열을 홈 API에 전달하거나 우승 통계를 다시 계산하지 않습니다. 구절판은 등록된 9개 슬롯과 배치 정보를 사용합니다. 이미지는 지연 로딩합니다.

기존 월드컵 홈의 검색·최근 등록·최근 플레이·카테고리·카드 기능은 새 목록 주소에서 계속 동작합니다. 예전 홈의 `?search=`, `?creator=`, `?focus=` 링크도 검색 조건을 보존해 새 목록으로 보냅니다.

## 검색용 HTML과 사이트맵

- 종합 홈과 월드컵 목록에 각각 다른 제목·H1·설명·대표 주소·언어별 대체 주소를 제공합니다. 종합 홈에서는 추가 구호 제목을 제외하고 중앙 로고의 사이트 이름을 단일 H1로 사용합니다.
- 한국어 홈 제목은 `이상형 월드컵·구절판·티어표·퀴즈·랜덤 뽑기 | 원픽게임`입니다.
- 새 월드컵 목록 제목은 `이상형 월드컵 | 원픽게임`이며 월드컵 전용 소개문을 제공합니다.
- 각 개별 월드컵의 실제 제목·후보 수·후보 이름을 사용하는 설명 생성 규칙은 유지합니다.
- 20개 언어 사이트맵에 새 월드컵 목록을 추가합니다. 기존 시작·결과·퀴즈·티어표·구절판·프리셋 주소는 삭제하지 않습니다.
- 초기 HTML에도 다섯 섹션과 실제 카드 링크를 포함합니다. 브라우저는 이 공개 데이터를 재사용하므로 첫 진입 때 같은 홈 데이터를 다시 요청하지 않습니다.
- 앞선 SEO 수정과 함께 적용할 수 있도록 `worldcupEntryInfo.cjs`와 `worldcup-view-routes.cjs`도 포함했습니다. 시작 페이지의 후보 수·결과 링크를 제공하고, 기존 `/stats/:id`는 대표 통계 주소인 `/result/:id`로 연결합니다.

## 적용 방법

1. ZIP 안의 파일을 프로젝트 루트에 같은 경로로 덮어씁니다. 전체 프로젝트 ZIP이 아닌 수정 파일 묶음입니다.
2. 기존 환경변수와 DB는 유지합니다. 새 환경변수·SQL·데이터 이전은 필요하지 않습니다.
3. 평소처럼 `npm run build`를 실행합니다. 기존 빌드 명령에 사이트맵 재생성과 `seo-shell.html` 복사가 포함되어 있습니다.
4. **프런트엔드와 `server.js`, `vercel.json`을 함께 배포합니다.** 정적 빌드만 교체하면 새 목록의 검색용 응답과 홈 API가 반영되지 않습니다.
5. 배포 후 `/ko`, `/ko/ideal-type-world-cup`, `/en/ideal-type-world-cup`, 기존 개별 월드컵·프리셋 주소, `/api/platform-home?lang=ko`, 언어별 사이트맵을 확인합니다.

기존에 제출한 개별 콘텐츠 URL을 옮기거나 새 주소로 다시 만들 필요는 없습니다. 검색 도구에서 새 목록 주소를 추가로 확인할 수 있습니다. 기존 주소 보존이 검색 순위 유지를 보장하는 것은 아닙니다.

## 검증

실제 공개 DB에 쓰지 않고 테스트용 데이터로 검사했습니다.

- `node tests/platform-home.cjs`: 20개 언어, 다섯 섹션 순서, 제목/전체보기 링크, 기존 ID, 인기 정렬, 번역, 썸네일 재사용, 캐시·부분 실패.
- `node tests/platform-home-routes.cjs`: Express 초기 HTML, 20개 언어 대표 주소·hreflang, 홈 API, 예전 검색 링크, 새 목록과 기존 개별 URL의 사이트맵 포함.
- `node tests/platform-home-production.cjs ../platform-home-build`: 실제 프로덕션 번들에서 한국어·영어·일본어·아랍어 홈 → 월드컵 목록 → 언어 변경, 예전 검색 링크, 창 크기 변경 후 렌더링 안정성.
- 월드컵 시작·통계 SEO, 티어표/구절판 제목 현지화, 공용 썸네일, 후보 가져오기와 비회원 사진 등록 회귀 검사를 통과했습니다.
- 프로덕션 빌드를 완료했습니다. 빌드 테스트에서는 실서비스 사이트맵 쿼리를 실행하지 않고 React 빌드 단계를 직접 실행했습니다.

프로덕션 번들 동작 검사는 JSDOM 환경에서 수행했습니다. 실제 Chrome/Edge 화면의 시각 검수와 운영 배포는 수행하지 않았습니다.
