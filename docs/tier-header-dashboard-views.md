# 티어표 버튼 위치 / 대시보드 구절판 조회수

## 변경
- 티어표 결과 헤더: 제목 → 작성자·프리셋 → 태그·설명 → 버튼 한 줄 순서입니다.
- 버튼은 박스의 마지막 자식으로 배치하고 양쪽 자동 여백으로 가운데 정렬합니다. 화면이 좁으면 행 내부를 가로 스크롤하며, 버튼은 여러 줄로 나뉘지 않습니다. 공유·좋아요·수정·삭제 동작과 노출 권한은 유지합니다.
- 관리자 상단 콘텐츠 표의 구절판 누적·오늘은 종전에 `get_admin_top_nine_stats_with_private`의 등록·나만 보기 완료 수를 표시했습니다. 조회가 이 두 칸에 반영되지 않는 원인은 표시 지표가 달랐기 때문입니다.
- 이 두 칸을 기존 `get_admin_top_nine_views_v1` 열람 통계로 연결했습니다. 누적은 현재 공개 구절판의 조회수 합계, 오늘은 한국 시간 기준 열람 기록입니다. 현존 수는 기존 공개 게시물 수를 유지합니다.
- 아래의 최근 열람 목록과 조회 기록 방식은 변경하지 않았습니다. 같은 탭 세션에서 같은 구절판은 한 번 기록하며, 과거에 기록되지 않은 열람은 복원하지 않습니다. 등록 완료 수에 조회수를 더해 합산하지 않습니다.
- 열람 통계가 없거나 실패하면 표에서 `—` 및 오류 안내를 보여줍니다. 실제 조회가 0일 때만 0으로 표시합니다.

## 적용
앞서 전달한 추천·비회원 업로드 업데이트가 적용된 프로젝트 기준의 추가 소스 패치입니다. 같은 경로로 덮어쓰고 빌드·배포합니다. 이번 표시 수정 자체는 추가 SQL이 필요 없습니다.

기존 열람 SQL이 적용되지 않았다면 다음 파일을 순서대로 실행해야 합니다. 편의를 위해 변경 없이 함께 첨부했습니다.
1. `supabase/20261115_top_nine_view_tracking.sql`
2. `supabase/20261116_admin_top_nine_views.sql`

기존 카운터를 초기화하는 작업은 하지 마세요. SQL은 반복 실행 가능하며 관리자 열람 RPC는 관리자에게만 허용됩니다. 서버 키 추가나 새로운 환경변수는 필요 없습니다.

## 검증
- CRA 빌드 성공.
- 실제 빌드 JS를 JSDOM에서 실행: 한국어 모바일 너비·영어 PC 너비에서 버튼 8개, 설명문 다음 위치, 박스 마지막 요소, 좌우 자동 여백, 줄바꿈 방지와 가로 스크롤 스타일 확인. 실제 브라우저 픽셀 측정은 아닙니다.
- `tests/admin-summary-top-nine-views.cjs`: 현존 23 / 등록 완료 69 / 열람 987 fixture에서 표가 23·987·32를 표시하는지 확인. 새로고침, SQL 미적용·잘못된 응답과 실제 0 구분 확인.
- 기존 관리자 열람 UI·SQL 테스트 통과: 관리자 권한, 한국 시간 날짜 경계, 최근 30건, 중복 제외 및 기존 카운터 보존.
- 운영 DB 조회·수정이나 운영 배포는 하지 않았습니다.
