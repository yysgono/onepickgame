# 이미지 전송량과 변환 사용량

이 패치는 트래픽 절감 가능성과 사진 식별 편의를 함께 고려합니다. 실제 절감액을 측정하거나 보장한 상태는 아닙니다.

게임에서 불러온 원본이 브라우저 캐시에 유효하게 남아 있다면 같은 URL을 재사용할 때 이미지 본문을 다시 내려받지 않을 수 있습니다. 이 경우 새 썸네일을 요청하는 것보다 유리합니다. 하지만 로드 이력만으로 현재 브라우저 캐시 보유 상태를 완벽히 판정할 수는 없습니다.

이번 패치는 MediaRenderer의 성공한 이미지 onLoad를 관찰해 최근 URL만 메모리에 저장합니다. 파일을 복제하거나 Cache Storage/localStorage에 이미지를 별도 저장하지 않습니다. 동일 탭의 일반적인 게임→결과 페이지 이동을 대상으로 한 힌트입니다. 강제 새로고침, 캐시 비활성화, URL 변경, 다른 탭, 캐시 만료/삭제에는 재다운로드가 발생할 수 있습니다.

안 불러온 Supabase 공개 이미지는 일정한 96×96px / 품질 70 / contain 변환 URL로 요청합니다. 화면 표시 크기는 48px(모바일 40px)입니다. 파일 용량이 반드시 특정 KB 이하가 된다는 보장은 없으며 원본의 형식과 내용에 따라 달라집니다. 외부 URL을 서버 프록시로 가져오지 않고, 서명 주소나 동영상은 임의 이미지 변환 대상으로 삼지 않습니다.

Supabase의 자동 이미지 변환은 별도 사용량 항목입니다. 2026-10-28 확인한 공식 문서상 변환 횟수 그 자체가 아니라 청구 기간에 변환된 서로 다른 원본 이미지 수를 기준으로 집계합니다. Pro 기본 포함량은 100개 원본 이미지이며 초과분은 1,000개 단위당 5달러 패키지 과금 안내가 있습니다. 실제 청구는 조직의 플랜, 할당량, Spend Cap과 사용량에 따릅니다. 이미지 다운로드 트래픽 비용은 이 변환 항목과 별개입니다.

공식 사용량 문서:
https://supabase.com/docs/guides/platform/manage-your-usage/storage-image-transformations
https://supabase.com/docs/guides/storage/serving/image-transformations

사용을 원치 않으면 REACT_APP_STATS_IMAGE_TRANSFORMS=false로 빌드/배포하세요. 이미지는 작은 크기로 보이지만 원본 URL을 사용합니다. 이번 패치가 Supabase 유료 설정이나 Spend Cap을 변경하지는 않습니다.

이미 변환 기능이 켜진 프로젝트에서는 통계표에서 새로운 공개 이미지를 보는 것이 변환 사용량으로 반영될 수 있습니다. 먼저 소수 게임으로 확인한 뒤 Supabase Usage의 Storage Image Transformations와 Egress를 함께 확인하세요. 테스트 코드의 이미지 주소는 실제 파일 요청 없이 모의 테스트에만 사용했습니다.
