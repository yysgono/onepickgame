# 홈 카드가 모두 비는 문제 수정

## 확인한 원인

기존 수정본은 `/api/platform-home`의 응답 또는 서버가 넣어 준 초기 데이터만 사용했습니다. API가 없는 CRA 개발 서버에서는 HTML/404 응답을 받았고, 공개 서버에서도 해당 API가 `{"error":"Not Found"}`를 반환하는 상태를 확인했습니다. 이 경우 공개 DB를 읽을 수 있어도 홈은 빈 목록에서 끝났습니다.

서버에 서비스 키만 있고 공개 키 환경변수가 없으면, 익명 홈 클라이언트를 만들지 못해 다섯 섹션을 모두 실패 상태로 내려주는 경로도 있었습니다. 이전 테스트가 성공한 홈 API를 중심으로 구성되어 이 환경 차이를 놓쳤습니다.

## 변경

- 홈 API가 404, HTML, 503, 잘못된 데이터, 네트워크 오류 또는 시간 초과를 반환하면 기존 앱과 같은 공개 Supabase 설정으로 다시 읽습니다.
- 서버의 초기 데이터에 실패한 섹션이 있으면 브라우저가 보완합니다. 이미 성공한 섹션은 유지합니다.
- 공개 조회용 클라이언트는 로그인 세션을 저장하거나 갱신하지 않습니다. 공개 키만 사용하며 서비스 키를 브라우저에 넣지 않습니다.
- 서버는 기존 anon 환경변수뿐 아니라 publishable 환경변수도 지원합니다. 환경변수가 없고 브라우저와 같은 프로젝트라면 기존 브라우저 공개 설정을 재사용합니다.
- 조회 실패와 실제 빈 목록의 문구를 구분합니다. 오류 문구는 20개 언어에 적용했습니다.
- 재시도 시 실패 캐시를 새로 읽습니다. 언어 변경·페이지 이탈 뒤에 늦게 온 응답이 화면을 덮어쓰지 않도록 취소 처리를 유지합니다.

카드 순서, 개별 게임 주소, 프리셋 원본 ID, 후보 데이터, 로그인·등록 기능은 유지합니다. 새 SQL이나 새 환경변수는 필요하지 않습니다.

## 적용

이 ZIP은 이전 종합 홈/월드컵 목록 분리 수정도 포함한 전체 수정 파일 묶음입니다. 이전 ZIP 대신 같은 경로에 덮어쓰세요.

- 로컬 개발: 실행 중인 개발 서버를 다시 시작하고 홈을 새로고침합니다. 별도 홈 API가 없어도 공개 데이터를 읽습니다.
- 운영: 기존 `npm run build`와 프런트엔드·서버 동시 배포를 진행합니다. 서버를 함께 반영해야 검색용 초기 HTML에도 카드가 채워집니다.
- 새 필수 파일: `src/seo/platformHomeData.js`, `src/utils/publicSupabaseConfig.js`, `src/utils/publicPlatformHome.js`. 함께 포함된 `supabaseClient.js`도 적용합니다.

운영 사이트에는 이 수정본을 직접 배포하지 않았습니다.

## 검증

실제 프로덕션 번들에서 API 404와 빈 실패 초기 데이터를 각각 재현해, 공개 DB 요청 후 월드컵·티어표·퀴즈·구절판·랜덤 뽑기 카드가 모두 표시되는 것을 검사했습니다. 데이터 응답은 테스트용 자료를 사용했습니다.

- `tests/platform-home-data.cjs`: API 누락, CRA HTML, 503, 네트워크 오류, 시간 초과, 초기 데이터 부분 실패, 취소, 양쪽 조회 실패, 실패 캐시 갱신.
- `tests/platform-home-server-public-client.cjs`: 공개 키 환경변수 없이 기존 서버 설정만 있을 때 공개 키로 홈을 조회하는지 확인.
- `tests/platform-home-navigation-production.cjs`: API 404/실패 초기 데이터 복구, 양쪽 조회 실패 후 재시도, 20개 언어 직접 접속, 늦은 응답 무시, 전체보기·로고 이동.
- 기존 빌드·언어 전환·창 크기 변경·기존 개별 URL·사이트맵·티어표/구절판 연결·비회원 사진 등록 검사도 통과했습니다.

새 코드의 화면 동작 검사는 JSDOM에서 수행했습니다. 공개 사이트의 누락 API는 브라우저에서 확인했지만, 수정본을 운영 사이트에 배포한 뒤의 화면 검수는 수행하지 않았습니다.
