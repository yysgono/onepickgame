원픽게임 v74 — 월드컵·티어표·퀴즈 통합 휴지통

적용 순서
1. Supabase SQL Editor에서 supabase/20261026_content_trash.sql 전체를 실행하세요.
2. 성공한 다음 ZIP의 파일을 프로젝트의 같은 경로에 덮어쓰세요.
3. 최신 소스로 다시 빌드하고 배포하세요. 기존 build 폴더를 그대로 배포하지 마세요.

SQL이 실패하면 프런트 파일을 먼저 배포하지 마세요. 이 SQL은 기존 운영자 권한 함수
can_publish_site_content()와 세 콘텐츠 테이블의 RLS를 확인합니다. 조건이 맞지 않으면
트랜잭션을 중단합니다. 오류 전문을 확인한 뒤 적용해야 합니다.

사용 방법
- 삭제하면 콘텐츠가 휴지통으로 이동합니다. 후보·문제·정답·이미지·통계는 유지됩니다.
- 운영자 대시보드의 통합 휴지통에서 종류를 선택하고 제목, ID, 원래 URL로 검색하세요.
- 복구하면 기존 ID로 다시 사용할 수 있습니다.
- 최소 30일 동안 영구삭제가 금지됩니다. 30일이 지나도 자동삭제되지 않습니다.
- 실제 영구삭제 전까지 복구할 수 있고, 영구삭제는 운영자가 직접 확인해야 합니다.
- 이미 과거에 물리적으로 삭제한 데이터나 파일을 되살리는 기능은 아닙니다.
- 별도 사본을 만드는 백업 기능이 아니라 원본을 보존하는 휴지통입니다.

이미지와 연결 데이터
- 휴지통 콘텐츠가 사용하는 Storage 이미지는 삭제·덮어쓰기로부터 보호합니다.
- 영구삭제는 DB 콘텐츠와 연결된 DB 데이터를 대상으로 합니다.
  Storage 파일의 자동 정리는 포함하지 않으며 파일 정리는 별도로 해야 합니다.
- 다른 독립 콘텐츠까지 연쇄 삭제될 관계가 있으면 영구삭제 전체를 중단합니다.
  이런 오류가 나면 관계를 점검해야 하며 강제로 삭제하지 마세요.
- 이전 버전 화면에서 직접 삭제하는 요청은 차단됩니다. 배포 후 화면을 새로고침하세요.
- 검색엔진·기존 CDN 캐시의 이전 화면은 즉시 사라지지 않을 수 있습니다.

검증 범위
- React 프로덕션 빌드 통과.
- 모의 PostgreSQL에서 권한, 휴지통, 복구, 30일 제한, 공유 이미지 보호,
  연결 콘텐츠 연쇄 삭제 방지 및 SQL 재실행 검증 통과.
- 관리자 화면, 홈 페이징, 퀴즈 SEO 및 이미지 정리 회귀 검사 통과.
- 실제 운영 DB, Storage REST, 배포 환경에서 실행한 것은 아닙니다.
- 운영 DB를 사용하는 사이트맵 생성까지 포함한 전체 npm 빌드 과정은 실행하지 않았습니다.
- 추가 런타임 패키지는 필요 없습니다. tests/content-trash-v74.cjs와 preflight 검사는
  개발 검증용 @electric-sql/pglite가 필요하며 운영 의존성에는 추가하지 않았습니다.
