그 다음 기존 방법대로 커밋·푸시·배포합니다. Git에서 원격 변경 충돌이 뜨면 강제 푸시하지 마세요.

서버 환경변수 SUPABASE_SERVICE_ROLE_KEY 확인:
- 기존에 올바른 서버 전용 키가 등록되어 있다면 다시 등록할 필요 없습니다.
- 저장소의 이름이 바뀐 env 백업에는 이 이름에 anon 키가 들어 있었습니다.
  그 값을 관리용 키라고 생각해 복사하면 안 됩니다.
- 실제 서버 전용 키는 Vercel 환경변수에만 넣고 REACT_APP_ 접두사를 붙이지 마세요.
- 키 값을 채팅, Git, 화면 캡처에 노출하지 마세요.
- 올바른 서버 키가 없으면 탈퇴 API는 실제 삭제를 완료할 수 없습니다.

[3. 적용 확인]
- /ko/admin 상단 요약 아래 '회원관리 · 탈퇴 신청 목록 보기'.
- 일반 회원은 조회/처리를 할 수 없어야 합니다.
- 실제 회원보다 먼저 직접 만든 테스트 회원으로 신청→처리→작성물 보존을 확인하세요.
- 본인 운영자와 관리자 계정은 이 버튼으로 삭제되지 않습니다.
- 블로그/공지/자유게시판 글쓰기에서 편집 도구와 이미지 붙여넣기를 확인하세요.

[4. 탈퇴 처리의 범위]
- 실제 로그인 계정과 프로필을 삭제하며 작성물은 공통 보존용 계정으로 연결합니다.
- 표시 이름은 '탈퇴한 회원'입니다. 보존용 시스템 계정과 설정을 임의로 삭제하지 마세요.
- 공개 이미지 파일을 복사하거나 URL을 바꾸지 않습니다.
- 게시물 본문/제목/사진 속 개인정보는 자동 판독해 삭제하지 않습니다. 별도 요청은 먼저 검토하세요.
- 비공개 파일·진행 중 업로드·예상하지 못한 DB 연결이 있으면 삭제를 멈춥니다.
- 실패하면 계정이 제한되거나 작성자 연결만 정리된 상태일 수 있습니다.
  목록에서 재시도하고, 서버 중단 후 잠금이 남으면 최대 5분 뒤 다시 확인하세요.
- 계속 실패한 상태를 완료로 간주하거나 Auth 계정만 따로 삭제하지 마세요.
- 구글·네이버 가입과 해당 제공자의 연결 해제는 아직 추가하지 않았습니다.
- 이 변경이 전체 보안/모든 기존 RPC/법적 준수 점검 완료를 의미하지는 않습니다.

[5. 공개 저장소의 인증정보 메모]
.gitignore에 해당 메모 파일을 제외하는 항목을 추가했습니다.
이미 Git이 추적 중인 파일은 .gitignore만으로 삭제되지 않습니다.
프로젝트 터미널에서 다음을 실행하면 컴퓨터 파일은 남기고 현재 Git 추적에서 제외합니다:

git rm --cached --ignore-unmatch -- "api key.txt" "passwords.txt" "앱 비밀번호.txt" "새 텍스트 문서.env.local"

이후 커밋·푸시해야 현재 저장소에서 빠집니다. 과거 커밋까지 사라지지는 않습니다.
실제 사용 중인 앱 비밀번호/비밀키가 들어 있었다면 발급 서비스에서 폐기·교체해야 합니다.
공개용 Supabase anon/publishable 키와 비밀용 키를 구분하세요. 공개용 키를 무작정 바꾸지는 마세요.
ZIP에는 실제 키·비밀번호 값이나 해당 메모 파일을 넣지 않았습니다.
