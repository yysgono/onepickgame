v109 게시판 검색용 HTML의 sanitize-html ESM 호환성 수정
기준 GitHub main 8ef529ef2965452479857ec280f50e791e0c443d

적용
1. ZIP 내용을 프로젝트의 같은 경로에 덮어쓰세요. vendor 폴더의 파일도 반드시 포함하세요.
2. 변경 파일 전부를 커밋/푸시하여 새 Production 배포를 기다리세요.
3. Vercel Node.js 설정은 24.x를 유지하세요.
4. 자유게시판/공지사항 주소를 직접 열어 새로고침하세요.
5. 정상일 때 Search Console 실시간 테스트 후 색인 생성을 요청하세요.
SQL이나 환경변수/새 패키지 설치는 필요 없습니다.

수정 내용
- sanitize-html 2.18.1과 htmlparser2 12.x를 하나의 CommonJS 파일로 미리 묶었습니다.
- rich-text-server.cjs는 이 파일을 읽어 Node의 require(ESM) 지원 여부에 의존하지 않습니다.
- 최신 보안 패치와 기존 HTML/URL/CSS 허용 정책을 유지합니다. 본문 정화를 우회하거나 패키지를 낮추지 않았습니다.
- package.json의 build 앞에 생성 단계를 추가하여 향후 패키지 변경 시에도 다시 생성합니다.
- 미리 생성한 vendor 파일도 포함하므로 Vercel의 서버/정적 빌드 순서에 의존하지 않습니다.
- 생성 스크립트는 기존 react-scripts에 포함된 webpack을 사용합니다.
- vendor NOTICES 파일에 묶인 패키지의 버전 및 라이선스 고지를 포함했습니다.

확인한 내용과 한계
Node 24에서 --no-experimental-require-module 옵션으로 기존 오류를 재현했습니다.
이 옵션을 켠 상태에서도 생성 및 수정된 sanitizer가 작동합니다.
실제 게시판 SEO 미들웨어를 사용한 모의 DB 테스트에서 자유게시판/공지사항 모두 HTTP 200과 index, follow를 확인했습니다.
브라우저/서버 HTML 정화 기존 회귀 테스트도 통과했습니다.
운영 서버의 실제 실행 옵션은 아직 확인되지 않았으며, 이 패치를 운영에 배포하지는 않았습니다.
이번 오류는 서버 측 모듈 문제이므로 React 전체 빌드나 운영 DB/사이트맵 조회는 추가 실행하지 않았습니다.

업데이트 관리
sanitize-html 등을 업데이트하면 npm run build:rich-text로 재생성하고 vendor 변경도 함께 커밋하세요.
자동 build에서도 재생성하지만 서버 빌드가 먼저 실행되는 환경을 위해 최신 vendor 파일을 커밋하는 것을 권장합니다.
