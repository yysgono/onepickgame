v112 기존 회원에 NAVER 로그인 연결
기존 v111 NAVER 로그인이 설치된 프로젝트용 수정 파일입니다.

적용 순서
1. Supabase > Authentication > Sign In / Providers > User Signups의 Allow manual linking을 켜고 Save changes.
   Allow users without email은 NAVER 제공자 설정에서 켜진 상태를 유지하세요.
   Google/이메일 설정을 끄거나 바꾸지 마세요.
2. ZIP의 src/ 수정 파일을 프로젝트의 같은 경로에 덮어쓴 뒤 커밋/푸시/배포하세요.
3. 기존 이메일/비밀번호 또는 Google로 로그인하세요.
4. 상단 프로필 메뉴를 열어 네이버 계정 연결을 누르세요.
5. 네이버 인증을 마치면 같은 UID에 네이버 identity가 추가됐는지 서버 Auth로 확인합니다.
6. 연결 성공 후 기존 로그인 방식과 네이버 양쪽으로 같은 회원인지 확인하세요.

이번 패치에는 새 SQL/패키지/환경변수가 없습니다. 기존 v111 SQL은 그대로 필요합니다.
기존 콘텐츠나 회원 데이터를 변경하는 SQL은 실행하지 않습니다.

중요: 이미 별도로 가입한 NAVER 계정
동일한 NAVER identity가 다른 Supabase UID에 이미 속해 있으면 연결은 거부될 수 있습니다.
화면에 다른 회원에 연결되어 있다는 안내가 표시됩니다.
이 패치는 이미 생긴 두 회원을 합치거나 삭제하지 않습니다. 콘텐츠도 이전하지 않습니다.
기존 계정을 유지하고 별도 NAVER 계정에 작성한 콘텐츠/댓글/개인정보 요청 등이 있는지 확인한 뒤 별도 정리가 필요합니다.
이메일 문자열을 같게 고치거나 Auth identity의 user_id를 직접 바꾸지 마세요.
운영자 자신의 이미 중복 가입된 NAVER는 이 제한에 해당할 수 있습니다.
Supabase의 Allow manual linking을 켜는 것만으로 기존 두 계정이 합쳐지지 않습니다.

안전장치
- 로그인한 회원을 Auth 서버 getUser로 확인하고 공식 linkIdentity API로 연결합니다.
- 현재 UID와 연결 후 UID가 같은지 확인하고, custom:naver identity가 실제 있는지 확인합니다.
- UID가 달라졌으면 성공 처리하지 않고 로컬 세션을 종료합니다.
- 브라우저 메모의 사용자 id는 권한을 부여하지 않으며 서버 인증 결과와의 비교용입니다.
- 연결 의도는 15분간 유효하며 성공/실패 후 정리합니다. 토큰은 URL 기록에서 지웁니다.
- 콜백은 연결 흐름과 신규 로그인 흐름을 구분합니다. 연결 중에는 닉네임 생성 RPC를 호출하지 않습니다.
- 새 로그인 버튼으로 시작하면 이전의 연결 요청 메모를 정리합니다.
- 이메일만으로 계정을 합치지 않으며, 사용자 입력으로 다른 회원 identity를 옮기지 않습니다.
- Google/이메일 로그인, v111 NAVER 신규 로그인과 기존 닉네임 동작을 유지합니다.
- 로그인/가입 화면에 기존 회원은 먼저 로그인 후 연결하라는 안내를 16개 언어로 표시합니다.
- 네이버 서비스 연결 해제 및 사이트 탈퇴의 관계는 v111 안내 그대로입니다.

검증
공식 linkIdentity 호출/로그인 필요/기존 연결/UID 유지/서버 identity 확인/중복 identity/설정 꺼짐/만료/계정 변경/URL 토큰 정리 테스트 통과.
연결 성공/충돌 안내 콜백 UI, 기존 첫 로그인 닉네임 및 Google/NAVER 로그인 회귀 테스트 통과.
CRA 프로덕션 컴파일 통과. 실제 운영 NAVER identity 연결은 수행하지 않았습니다.
